# זול-לי · שרת המחירים

הקוד הזה מושך את קבצי המחירים שרשתות השיווק חייבות לפרסם לפי **חוק המזון (שקיפות מחירים)**, מאחד את המוצרים לפי ברקוד, ומחשב סל קניות כולל מבצעים, מועדוני לקוחות ודמי משלוח. אין בו תלות בספריות חיצוניות, רק Node.js 20 ומעלה.

## מה יש כאן

| קובץ | מה הוא עושה |
|---|---|
| `src/adapters.js` | איפה כל רשת מפרסמת את הקבצים: שופרסל (אתר רשימות), רמי לוי, יוחננוף ואושר עד (פורטל Cerberus), וויקטורי וקרפור (להשלים כתובת) |
| `src/parse.js` | פענוח הקבצים: gzip/zip, קידוד UTF‑8/UTF‑16, קובצי מחירים, מבצעים וסניפים, כולל הבדלים בשמות התגיות בין רשתות |
| `src/normalize.js` | איחוד כל הרשתות לקטלוג אחד לפי ברקוד, וקובץ מקוצר לאפליקציה |
| `src/compare.js` | חישוב סל: מבצעי "X ב‑Y", אחוז הנחה, "השני ב‑", מבצעי מועדון, מינימום הזמנה ודמי משלוח |
| `src/fetch.js` | מריץ את הכל וכותב ל‑`data/` |
| `test/run.js` | בדיקות על קבצים לדוגמה בפורמט הרשמי |
| `.github/workflows/update-prices.yml` | הרצה אוטומטית כל 3 שעות ב‑GitHub Actions, בחינם |

## הפעלה

```bash
node test/run.js                                   # בדיקות, בלי אינטרנט
node src/fetch.js --chains=shufersal --stores=3    # ניסיון ראשון, 3 סניפים בלבד
node src/fetch.js --online-only                    # כל הרשתות, רק סניפי האונליין
```

הפלט ב‑`data/`:
- `summary.json` — לכל ברקוד: שם, יצרן, כמות, והמחיר הזול בכל רשת. זה הקובץ שהאפליקציה טוענת.
- `db.json` — הכל: מחיר בכל סניף ורשימת המבצעים.
- `report.json` — מה הורד ומה נכשל.

## הרצה אוטומטית בחינם

1. פותחים מאגר (repository) חדש ב‑GitHub ומעלים את התיקייה.
2. ב‑Actions מפעילים את "Update prices" ולוחצים Run workflow.
3. כל 3 שעות הקבצים המעודכנים יופיעו בענף `data`, ואפשר לקרוא אותם ישירות מהאפליקציה דרך כתובת ה‑raw של GitHub או דרך GitHub Pages.

## מה עוד צריך לבדוק לפני עלייה לאוויר

- **כתובות הפורטלים.** הקוד נכתב לפי המבנה המוכר של הפורטלים, אבל לא נבדק מול האתרים עצמם. לבדוק כל רשת מול הרשימה הרשמית של משרד הכלכלה ב‑gov.il ("שקיפות מחירים ברשתות השיווק"), ולהשלים את הכתובות של ויקטורי וקרפור ב‑`src/adapters.js`.
- **מוצרים בלי ברקוד אחיד.** ירקות, מאפים ומוצרי מעדנייה מקבלים קוד פנימי שונה בכל רשת. הם נשמרים בנפרד לכל רשת (`shufersal:123`), וצריך שכבת התאמה לפי שם (למשל "עגבניות" בכל הרשתות) — זה השלב הבא.
- **פענוח מבצעים.** הקוד מכסה את סוגי המבצעים הנפוצים. מבצעים על סכום קנייה, מתנות ומבצעים משולבים בין מוצרים שונים דורשים טיפול נוסף.
- **מחירי אונליין.** המחיר באתר האונליין לפעמים שונה מהסניף. לכן כדאי להשוות לפי סניף האונליין של כל רשת (`--online-only`).
- **דמי משלוח וחלונות משלוח** לא נמצאים בקבצי השקיפות. אותם צריך לקחת מאתרי הרשתות או מהסכם שיתוף פעולה.

## בדיקות

### בדיקות השרת
```
node test/run.js
```
פענוח קבצי המחירים, התאמה לפי ברקוד וחישוב הסל. לא צריך התקנה, רק Node 20 ומעלה.

### בדיקות האפליקציה (דפדפן)
הבדיקות פותחות את `app/zul-li.html` בכרומיום דרך Playwright, עם קבצי הנתונים של האפליקציה.

התקנה, פעם אחת:
```
pip install playwright==1.48.0
python -m playwright install --with-deps chromium
```
הנתונים: ענף gh-pages, או בנייה מקומית מענפי הנתונים:
```
git fetch --depth 1 origin gh-pages && git worktree add site origin/gh-pages
# או: git fetch --depth 1 origin data bd geo images && bash tools/build_app_data.sh site
```
הרצה:
```
python test/browser/run.py --data site            # כל החבילה (כ-6 דקות)
python test/browser/run.py --data site --only qa,sec3
```

| בדיקה | מה נבדק |
|---|---|
| `qa` | 39 בדיקות ליבה: פענוח הדבקה, חשבון הסל, מיון ההשוואה, כמויות, ביטול, שמירה, מצב כהה, גלילה לצד |
| `qa4` | כפילויות ולחיצה כפולה על הזמנה |

| `rf4`, `edit` | שאלות הדיוק (חלב שיבולת שועל, מעדן, גבינה, נייר טואלט), תיקון שם ובחירת מוצר אחר |
| `pick` | בחירת רשת מכרטיס ההשוואה והזמנה ממנה |
